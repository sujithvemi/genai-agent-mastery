TermDefinitionWhere
A2AAgent2Agent, an open protocol for agents to discover each other through agent cards and exchange tasks and messages.Chapter 5
ADLC gateThe release gate of the agent development lifecycle: reads the manifest, derives the tier and required controls, and refuses promotion unless generated conformance shows every control bound and firing.Chapter 15
Agent cardA description of an agent (purpose, owner, tools, data, autonomy); in A2A, a signed document advertising an agent's skills and endpoint.Chapter 5
Agent identityAn identity issued to an agent itself: a workload identity, a directory object with an owner and sponsor, or a broker of users' tokens, depending on the vendor.Chapter 27
AI gatewayA gateway for model traffic: token-based limits, token metrics, semantic caching, backend pools with circuit breaking, model pinning.Chapter 25
Allowlist (evidence)The rule that evidence records contain only enumerated fields, so nothing unexpected is recorded.Chapter 21
AnchorA copy of the evidence chain's head hash stored outside the log, in immutable storage, so a rewrite of the whole log is detectable.Chapter 22
Annex IIIThe EU AI Act annex listing high-risk use areas (employment, credit, essential services and others); obligations apply from 2 December 2027 after the Omnibus.Chapter 48
Approval grantA signed, single-use authorisation bound to the hash of one exact action, verified at the PEP before execution.Chapter 19
ASI01–ASI10The ids in OWASP's Top 10 for Agentic Applications (version 2026).Chapter 32
Backend poolA set of model deployments behind an AI gateway, with priorities, weights and circuit breaking, used to spill from reserved to pay-as-you-go capacity.Chapter 29
Blast radiusOne of the five tiering axes: how many records or systems a single mistake can reach.Chapter 13
Business associate agreement (BAA)The HIPAA contract required before a service may receive protected health information.Chapter 49
ChokepointThe single function every tool call passes through, where the PEP sits.Chapter 16
Circuit breakerA mechanism that stops calling a failing dependency for a time so callers fail fast.Chapter 29
Conditional writeAn atomic "change only if" operation in a store, used to prevent write skew on budgets and counters.Chapter 28
Conformance (generated)The report of which controls are bound and fire for an agent, produced by running checks in the build, never edited by hand.Chapter 15
Context engineeringDeciding what enters the model's context window at each step: instructions, tools, retrieved content, memory, history.Chapter 3
ControlA rule with an objective, trigger, owner, evidence, test method and exception path.Chapter 14
Control decision rateRefusals per control per thousand calls, monitored for sharp changes rather than levels.Chapter 31
CRITICAL treatmentThe hardening at the top tier: non-waivable approvals, mandatory signed human approval, real-time oversight, executive sign-off.Chapter 13
CrosswalkA mapping between your controls and an external framework's requirements; as code, every cell carries a status and how it was verified.Chapter 48
Delegation (token exchange)Obtaining a narrower token that represents "this agent acting for this user", recording both.Chapter 27
Deployer and providerEU AI Act roles: the provider places a system on the market; the deployer uses it under its authority. Duties differ by role.Chapter 48
Digest (sign-off)A hash over the governed configuration that a sign-off approves; any change makes the sign-off stale.Chapter 38
Durable executionRunning long processes as code that survives crashes by recording each step's result and replaying from history.Chapter 26
Earned autonomyGranting an agent more autonomy per action class on measured evidence, revocable on a trigger, capped by tier.Chapter 50
EffectAny change an agent causes outside itself: a write, a payment, a message sent.Chapter 11
Effect-aware retryA retry policy that never repeats a turn after an effect completed in that attempt.Chapter 29
Enforcement pointWhere a control is applied: design time (the gate), run time (the PEP, gateways) or the evidence plane.Chapter 12
Evidence planeThe subsystem that records decisions and effects completely, in order, signed and anchored, as the system of record for defence.Chapter 22
Exception pathThe documented way a control may be waived, by whom and with what compensation; none for non-waivable controls.Chapter 14
FalsifierA test that disables a control and expects a failure, proving the control is what makes the result pass.Chapter 24
Fleet-firstAuthoring controls and tiers for the whole fleet, with each control's scope intrinsic to it, rather than per agent.Chapter 13
Golden setA curated set of tasks with expected outcomes used to gate releases.Chapter 23
GPAIGeneral-purpose AI model, in EU AI Act terms; obligations fall mainly on model providers since 2 August 2025.Chapter 48
GroundingConstraining a model's answer to supplied sources, with citations that can be checked.Chapter 4
HarnessThe code around a model that runs the agent loop: prompts, tool calls, context, memory and stopping rules.Chapter 1
Hash chainA sequence of records in which each includes the hash of the previous one, so edits are detectable.Chapter 22
Idempotency keyAn identifier that lets a target system recognise and ignore a repeated request.Chapter 26
Inventory (registry of record)The authoritative list of agents, tools and MCP servers with owners and states; unregistered subjects are refused.Chapter 45
KV cacheThe stored attention keys and values for tokens already processed, the main memory cost of serving long contexts.Chapter 9
Little's lawL = λW: items in flight equal arrival rate times time in system; used to size concurrency.Chapter 33
MCPModel Context Protocol, an open protocol for exposing tools, resources and prompts to models.Chapter 5
MCP pinA recorded hash of a tool's name, description and schema; a change withholds the tool until re-reviewed.Chapter 36
Minimum viable governanceThe seven items every later control depends on: inventory, tiering, approvals and kill switch on CRITICAL, a chokepoint, evidence, a gate, a rulings log.Chapter 51
Model pinThe provider, model id, version and settings an agent is approved to use; a change re-gates.Chapter 10
Model risk managementA bank's framework for inventory, validation and monitoring of models; in the US now SR 26-2.Chapter 49
Monotone-restrictiveA property required of model-based classifiers on the enforcement path: they can only make a decision stricter.Chapter 20
OutboxWriting an event to a table in the same transaction as the state change, then publishing it, so neither is lost.Chapter 26
OverlayA versioned layer that adds controls, tier floors, retention and roles on top of a generic core, never removing anything.Chapter 49
Paved roadThe platform, templates and pipeline that make the governed way the easiest way to ship.Chapter 50
PDPPolicy decision point: evaluates policy on facts and returns allow or deny with reasons.Chapter 16
PEPPolicy enforcement point: intercepts the action, asks the PDP, and enforces the answer.Chapter 16
PIPPolicy information point: supplies trusted facts to the PDP from systems of record.Chapter 16
Prefix cachingReusing computation for a shared prompt prefix across requests; reduces cost and latency, and must be scoped by tenant.Chapter 9
Prompt injectionInstructions placed in content the agent reads, intended to change what it does.Chapter 20
Provenance envelopeMetadata travelling with cross-agent content saying where it came from, so it is treated as data.Chapter 5
Provisioned throughputReserved model capacity bought for a term, with spill-over to pay-as-you-go.Chapter 33
ReachabilityWhether some input the PIP can build makes a policy rule fire; unreachable rules are removed.Chapter 24
Red-team corpusA versioned set of attacks run in CI against the enforcement plane.Chapter 24
Run APIAn API that starts a run (202 with an id), streams resumable events, and accepts approvals and cancellation.Chapter 25
SagaA sequence of local transactions with compensating actions instead of a distributed transaction.Chapter 26
SandboxAn isolated environment for code or browser execution with no ambient credentials and limited egress.Chapter 36
Semantic cachingReturning an earlier answer to a similar question; a data store that must be scoped by tenant and permission.Chapter 25
Separation of dutiesThe rule that the requester of an action cannot approve it.Chapter 19
Shadow decision pointA second engine that evaluates every decision for comparison but never acts.Chapter 47
SLI, SLO, error budgetA measured indicator, its target, and the allowed shortfall that governs release pace.Chapter 31
Speculative decodingGenerating draft tokens with a small model and verifying them with the large one to cut latency.Chapter 9
SPIFFEA standard for workload identities and their credentials, used by GEAP Agent Identity.Chapter 27
TierLOW, MEDIUM, HIGH or CRITICAL, derived from five axes by highest-wins banding.Chapter 13
Tool gatewayA gateway between agents and tools that authenticates agents, applies policy and pins, and routes MCP and A2A.Chapter 25
Trajectory evaluationScoring the sequence of steps and tool calls an agent took, not only its final answer.Chapter 39

Typed outputA response constrained to a schema and validated before use.Chapter 2
Verify cellA crosswalk cell tagged as not yet checked against a primary source.Chapter 48
WaiverA time-limited, owned exception to a control with a compensating control.Chapter 50
