PART I · CHAPTER 6

Orchestration and the meta-harness

Most useful agent systems are not one agent in a loop. They are workflows with model judgement inside some steps, graphs of specialised workers, or, increasingly, a coordinator that delegates typed work to other harnesses it does not control. Each shape changes where decisions are made and where controls must sit.

6.1Workflows and agents

Generic Anthropic's "Building effective agents" (December 2024) drew the distinction that clarifies most orchestration debates. A workflow orchestrates models and tools through predefined code paths; an agent lets the model direct its own process and tool use. Workflows are predictable and cheap to govern; agents are flexible and harder to bound. The advice that follows is the right default for enterprise work: start with the simplest thing (often one model call with retrieval), use a workflow when the steps are known, and use an agent only where the path genuinely cannot be fixed in advance. Keep model judgement inside nodes and keep the edges deterministic where you can.

pm-agent pm-agent's planning graph combines three: a planner that decomposes the request (orchestrator), a router that sends work to workers by type, and a critic that screens the plan before anything is proposed (evaluator), whose blocking screen is where the output guard runs.

6.3Typed state graphs

pm-agent ADR-0001 chose orchestration as a typed state graph: nodes are agents or stages with Pydantic contracts, edges are deterministic where possible, model judgement is confined inside nodes, human-approval gates are graph interrupts, and checkpoints are Postgres-backed. The runtime library (LangGraph) sits behind an owned Orchestrator interface, and an import-firewall test keeps LangGraph inside platform/runtime/. The properties that matter:

  • Typed contracts between nodes make every hand-off checkable, which is where shape slips get caught (Chapter 2).
  • Deterministic edges mean "what happens next" is code, testable without a model.
  • Interrupts as approval gates mean a run can stop before any effect, wait, and resume or end with no write.
  • Checkpoints make runs durable across waits, crashes and deployments (Chapter 26).

6.4When many agents help

Generic Multi-agent systems are fashionable, and the evidence is mixed in an instructive way. Anthropic reported that its orchestrator-worker research system, with parallel sub-agents, outperformed a single-agent baseline by about 90% on an internal evaluation while using roughly fifteen times the tokens of a chat interaction. The gain came from parallel exploration of breadth-first questions; the cost is tokens, latency, coordination failures and a much larger governance surface. The harness study found coordinator-worker shapes in seven of eleven coding agents, with sub-agent coordination kept in-process in eight of the nine multi-agent systems. Use many agents when the work is genuinely parallel and the budget allows; otherwise a single agent with good tools and a workflow around it is easier to make reliable and to govern.

6.5The meta-harness

Generic A meta-harness coordinates whole harnesses from above, with no editing loop of its own. The first public example, Databricks' Omnigent (June 2026), treats coding harnesses (Claude Code, Codex, OpenCode, Hermes, Pi, Cursor) as interchangeable components behind one API, adding cross-harness policies, a uniform sandbox and shared sessions. OpenHands does something similar through ACP, hosting other harnesses as back-ends. The pattern matters to an architect for two reasons: the executor layer is becoming a commodity you choose per task, and governance has to work across executors you did not build.

6.6pm-agent as a meta-harness

pm-agent pm-agent's direction is a meta-harness for the software product lifecycle: it keeps a product's plan, requirements, decisions, work and releases in step, and delegates the work itself to executors. Three ADRs define the shape:

  • A domain-neutral ledger (ADR-0007): generic artefact kinds (intent, requirement, decision, work item, deliverable, verification, release, feedback) with typed links (derives from, satisfies, implements, verifies, decided by, supersedes, released in…). The ledger is a derived index rebuilt from the systems of record, not a system of record itself; losing it loses only a cache. Lifecycle packs are versioned data (software first; other lifecycles such as UX design later), and drift is a failed check whose findings are fixable by typed actions.
  • An executor contract (ADR-0008): each executor declares its capabilities, accepts a delegation (a typed action with retrieved targets, a context pack and constraints) only with eligibility and a signed approval, runs in its own sandbox with its own credentials, and returns a proposal verified against acceptance criteria before anything is linked as done. One shared conformance suite every executor must pass.
  • Governance as each release's definition of done (ADR-0004): every new effect is a typed action with an eligibility rule, a hostile-planner proof and an eval case; tiers re-derived and gates passed for every profile touched; evidence signed; residuals disclosed.

6.7Governing a graph of agents

Generic Four rules carry across every orchestration shape, and each is grounded in a decision in your builds:

  1. A plan is not an authorisation. A coordinator's decision to delegate does not permit the worker's acts; each act is decided on its own facts at its own enforcement point.
  2. Messages carry no authority (D40). What one agent tells another is data.
  3. Tiers belong to nodes; edges get their own controls (D40). Do not compose a super-agent tier.
  4. Executors never get the coordinator's keys (ADR-0008). Delegated work runs on delegated, narrower authority, and its output is a proposal until verified.

6.10In the room

In the room
  • "We want a multi-agent architecture." "For which part of the work is parallel exploration worth roughly ten times the tokens and a larger control surface? Start with a workflow and add agents where the evidence says they pay."
  • "Can one orchestrator drive all our coding agents?" "Yes, as a meta-harness: it decides and verifies, they execute in their own sandboxes on narrower credentials, and their output is a proposal until checked."
