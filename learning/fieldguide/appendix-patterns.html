C.1How to use the catalog

The book's recurring designs in one place: 34 patterns in six groups, each with the problem it solves, the mechanism, where the book explains it, where your builds implement it, and the failure to watch for. Use it as a checklist when reviewing a design: for each effect an agent can cause, which of these patterns protect it?

C.2The patterns

Enforcement

Chokepoint

Problem
Effects can happen through many code paths, so a check in one is bypassed by another.
Mechanism
One function every tool call must pass; tools are not callable any other way, and a test proves it.
In this book
Chapter 16
In your builds
ARB chokepoint.py; pm-agent ToolChokepoint
Watch for
A second path added later (a framework host, a batch job) that skips it.

PEP, PDP and PIP

Problem
Mixing enforcement, decision and fact-gathering makes policy untestable and lets the model supply its own facts.
Mechanism
The enforcement point asks a decision point, which reads trusted facts from information points; each is replaceable behind a seam.
In this book
Chapter 16
In your builds
ARB enforcement/plane.py, pip.py, platform/policy/
Watch for
A PIP that echoes the tool arguments.

Deny by default, conservative facts

Problem
Policy languages fail open in subtle ways (undefined terms, unparsed conditions).
Mechanism
allow defaults false; every fact read with a worst-case default; an empty-request test.
In this book
Chapter 17
In your builds
ARB D18
Watch for
A deny rule that reads a missing field and silently stops firing.

Default deny with one positive allow

Problem
An engine that cannot parse a condition makes deny rules fail open.
Mechanism
Write each control as a single allow rule under default deny, so a parse failure is loud.
In this book
Chapter 47
In your builds
ARB AGT spike
Watch for
Mixing deny rules back in for convenience.

Monotone-restrictive classifiers

Problem
Model-based detectors are probabilistic; letting them authorise makes a control as weak as the detector.
Mechanism
A classifier on the enforcement path may only refuse or escalate, never allow; compose so screening only restricts.
In this book
Chapter 20
In your builds
ARB D52
Watch for
A "safe" verdict used to skip an approval.

Resolve, don't compare

Problem
Identities arrive in many spellings; string comparison lets a variant through.
Mechanism
Resolve every principal to one subject id from a directory before deciding.
In this book
Chapter 18
In your builds
ARB D33
Watch for
Comparing emails case-sensitively, or trusting a display name.

Messages carry no authority

Problem
In multi-agent systems, another agent's output can carry injected instructions.
Mechanism
Content from other agents is data; edges are declared; provenance travels with it; effects still pass the PEP.
In this book
Chapter 5
In your builds
ARB D40, CTL-0016–0019
Watch for
An orchestrator that executes a sub-agent's "next step" verbatim.

Three gateways

Problem
One "API gateway" cannot govern callers, model traffic and tool traffic at once.
Mechanism
An edge gateway for callers, an AI gateway for model traffic (tokens, pools, pins), an agent or tool gateway for reach, with your PDP attached to the last.
In this book
Chapter 25
In your builds
ARB model and tool gateways (D53, D63)
Watch for
Token limits at a request-counting gateway.

Approvals and identity

Signed approval grant

Problem
A boolean "approved" can be forged by the model or replayed.
Mechanism
An approver signs a grant bound to the exact action's hash; the PEP verifies it once, before executing.
In this book
Chapter 19
In your builds
ARB D20; pm-agent approval gate
Watch for
Grants that are not single-use, or bound to a session rather than an action.

Delegation that narrows

Problem
Passing user tokens onward grants full authority and hides the agent.
Mechanism
Token exchange to a narrower, shorter token naming both subject and actor; credentials held by a vault or gateway.
In this book
Chapter 27
In your builds
pm-agent on-behalf-of reads (PM CTL-0020)
Watch for
The agent holding users' refresh tokens.

Friction by design

Problem
Approvers rubber-stamp under volume.
Mechanism
Rate limits, cooling-off, batch caps, sampled second review and a legible payload; measure dwell time and window share.
In this book
Chapter 19
In your builds
ARB D35, D43
Watch for
Treating approval latency as the only metric.

Earned autonomy

Problem
Autonomy granted by enthusiasm is withdrawn only after an incident.
Mechanism
Promote per action class on measured evidence; demote on a trigger; the tier sets the ceiling.
In this book
Chapter 50
In your builds
ARB CRITICAL treatment
Watch for
Promotion after a good demo.

Evidence

Evidence before effect

Problem
If the effect happens and the record fails, the action is unrecorded.
Mechanism
Append the decision record first; refuse the effect if the write fails.
In this book
Chapter 22
In your builds
ARB GBL-EVID-01
Watch for
Async logging "for performance".

Hash chain, signatures and anchors

Problem
An append-only log can still be rewritten end to end.
Mechanism
Each record carries the previous hash; records are signed; the head hash is anchored outside the log in immutable storage on a fixed window.
In this book
Chapter 22
In your builds
ARB D21, D28, D34; GCS bucket lock
Watch for
Signatures produced but never verified (finding F-01).

Allowlist, not redaction

Problem
Redaction misses new fields; evidence leaks what it should not.
Mechanism
Records contain only fields on an allowlist; everything else is dropped.
In this book
Chapter 21
In your builds
ARB D25
Watch for
Free-text "reason" fields copied in whole.

Traces as a view of evidence

Problem
Telemetry and evidence diverge, and nobody knows which is right.
Mechanism
Evidence is the system of record; spans carry evidence ids; a join check verifies both directions.
In this book
Chapter 31
In your builds
pm-agent tracing join
Watch for
Using sampled traces for audit.

Gate and change

Control as contract

Problem
Controls described in prose cannot be tested or owned.
Mechanism
Every control states objective, trigger, owner, evidence, test method and exception path.
In this book
Chapter 14
In your builds
ARB governance/catalog/
Watch for
A trigger nobody can compute.

Fleet-first tiering

Problem
Tiers decided per agent drift and invite negotiation.
Mechanism
Axis values in the manifest; one banding rule derives the tier; controls declare their own minimum tier and scope.
In this book
Chapter 13
In your builds
ARB D14, D39
Watch for
Overriding a derived tier "just this once".

Generated conformance

Problem
A hand-maintained status table can be edited to look deployable.
Mechanism
The gate reads a conformance report generated in the run by checks that make each control fire.
In this book
Chapter 15
In your builds
ARB D27; make gov-fleet
Watch for
Committing the report.

Sign-off bound to a digest

Problem
An approval of version 1 silently covers version 2.
Mechanism
The sign-off records a digest of the governed configuration; any change makes it stale and the gate refuses.
In this book
Chapter 38
In your builds
ARB CTL-0022, D59
Watch for
Behaviour-setting inputs left out of the digest (finding F-06).

Reachability as a test

Problem
A rule nobody can trigger reads as enforcement.
Mechanism
Every fact a policy reads has a producer; a test proves each rule can fire.
In this book
Chapter 24
In your builds
ARB D30, D36; test_no_dead_policy.py
Watch for
Policy written ahead of its data source.

Falsifiers and mutation

Problem
Green tests can be blind.
Mechanism
Disable a control or a rule and check that some test fails; keep the falsifier in the suite.
In this book
Chapter 24
In your builds
ARB D56; the AGT fixture finding
Watch for
Parity suites that never mutate.

Revisit trigger, not a date

Problem
Calendar reviews of rejected options get skipped or rubber-stamped.
Mechanism
State the observable condition that reopens the decision, and a test that detects it.
In this book
Chapter 47
In your builds
ARB D63
Watch for
Triggers nobody watches.

State, reliability and cost

Conditional decrement or reservation

Problem
Concurrent replicas each read a budget and overspend it (write skew).
Mechanism
Make read-decide-write one operation in the store, or reserve before acting and reconcile.
In this book
Chapter 28
In your builds
ARB D58
Watch for
"Strongly consistent reads" mistaken for protection.

Idempotency keys from run and step

Problem
Retries and replays repeat effects.
Mechanism
Derive a key from the run and step, honoured by the target system.
In this book
Chapter 26
In your builds
ARB CTL-0006
Watch for
Keys generated per attempt.

Effect-aware retries

Problem
A retry after an effect duplicates it.
Mechanism
Retry a turn only for retryable errors and only if no effect completed in the attempt.
In this book
Chapter 29
In your builds
ARB D71
Watch for
Library retries below the turn.

Run API: 202 and events

Problem
Minutes of agent work do not fit a synchronous request.
Mechanism
Start returns a run id; progress streams as resumable events; approvals and cancel are their own endpoints.
In this book
Chapter 25
In your builds
pm-agent run model
Watch for
Holding a connection open for the whole run.

Durable execution by replay

Problem
Long runs with waits lose their place on a crash.
Mechanism
Record each step's result; on recovery, replay from history and execute only what has no record.
In this book
Chapter 26
In your builds
pm-agent checkpoints and interrupts
Watch for
Non-deterministic workflow code.

Architecture and delivery

Seams with fakes

Problem
Vendor SDKs leak into the core and make it untestable and non-portable.
Mechanism
Every vendor binding behind a protocol with a fake; an import firewall test keeps SDKs out of the core.
In this book
Chapter 7
In your builds
ARB platform/; D32
Watch for
A convenience import that crosses the firewall.

Frameworks as hosts behind gateways

Problem
A framework's pins block upgrades of others, and each framework enforces differently.
Mechanism
Run other frameworks out of process, behind governed model and tool gateways, and test decision equivalence.
In this book
Chapter 35
In your builds
ARB D53, D51
Watch for
A host that rewrites tool arguments.

Keyless pipeline

Problem
Long-lived CI keys leak and cannot tell which workflow used them.
Mechanism
Workload identity federation per job, trust scoped to repository and ref, the gate as a required check.
In this book
Chapter 30
In your builds
GAM M0/M1; ARB ci.yml
Watch for
A provider that trusts every repository in the organisation.

Core plus overlay

Problem
Client or sector specifics leak into reusable code.
Mechanism
A generic core and an overlay that only adds and tightens, with provenance per rule.
In this book
Chapter 49
In your builds
Capstone B7
Watch for
An overlay that removes a core control.

Centralise, federate, normalise, prove

Problem
No platform sees the others.
Mechanism
Central rules, registry, evidence and gate; enforcement through each platform's native points plus your own checkpoint; one evidence schema; parity tests across paths.
In this book
Chapter 45
In your builds
ARB D22, D51, D53

Trusting a vendor's inventory as the registry of record.

Crosswalk as code, four numbers

Problem
Compliance mappings drift and overclaim.
Mechanism
Versioned cells with Verified or Verify tags; implemented, mechanism, not-built and partial; tests that keep it honest.
In this book
