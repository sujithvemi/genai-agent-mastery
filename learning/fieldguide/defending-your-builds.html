54.1The method

Your build The reference build already has the discipline you need, written down in docs/showcase/CLAIMS_CARD.md: every "say" line has a command or file that keeps it true; if a sentence isn't there, don't say it. A defence built on that rule has five habits:

  1. Claim, then artifact. Two sentences of answer, then a pointer someone can open or run. "That's covered by test_…; the short answer is X; I'll send the evidence after the session."
  2. Every figure carries its date, the word "synthetic" where it applies, and its set size. "7 of 26 synthetic golden expectations met live on 2026-10-16" is defensible; "about a quarter" is not.
  3. Counts carry their scope. The red-team corpus (41 attacks) and the module suites (42 attacks) are counted separately; say which.
  4. Versioned statements about other people's products. AGT is "at agent-governance-toolkit-core 5.0.0, …", never "AGT fails open".
  5. "Not built; here is how we would do it" is a complete answer. Never let a "how we'd do it" sound like "we have it".

The rest of the chapter applies those habits at architect depth. For seller-level phrasing, the build's own docs/showcase/CLIENT_QA.md (25 rows, 8 starred) is the source; this chapter is what you say when the follow-up question goes one level down.

54.2The reference build in ninety seconds

Say it like this

"We built a competent customer-service agent with four tools and no governance, ran it on a real local model, and catalogued fifteen ways it could cause harm; in that first live run the model refused four of six adversarial refunds on its own, and money still moved twice. Each gap became a control with an owner, a trigger, evidence and a test. A five-axis tiering engine decides which controls each agent needs; a fail-closed gate blocks deployment until a conformance run, generated on that machine, proves each one fires; and every tool call goes through one chokepoint to a real policy engine, with a signed, hash-chained, externally anchored record written before the effect. A red team with a fully compromised model ran 41 attacks; one moved money, and it was fixed. A second agent with a different risk shape onboarded with zero framework changes, and the edge between them is governed as its own object. Since then: model budgets and pinning, sign-off bound to a configuration digest, an agent inventory, MCP tool pinning, content safety and typed cited answers, eight bindings exercised against a real GCP project, and a fairness measurement we are holding rather than gating because its criterion can't yet tell noise from bias."

54.3pm-agent in ninety seconds

Say it like this

"pm-agent is a governed product that helps project and product managers keep a software product's plan and its systems of record in step: it reads Jira and the repository, proposes plans and changes, and applies them only through typed actions a deterministic eligibility policy permits and a human approves. It forked the reference build's chassis and runs on LangGraph with Postgres checkpoints, so a run can park for approval and resume. Its biggest lesson was about injection: after a dozen rounds of improving a text detector, held-out acceptance stayed at 56%, so we stopped detecting and started containing, with typed effects, eligibility rules, display-only written text and provenance lanes. Each release's definition of done is the same five governance items, and the next releases add more of the lifecycle and executors like coding agents, each behind one shared contract."

54.5Questions from an architect or interviewer

QuestionAnswerEvidence
Why a chokepoint in process rather than a gateway?Both. In process it sees the most context (the turn's retrieval, the verified principal, the exact arguments) and can demote outputs; for hosts we don't control there are model and tool gateways driving the same plane, and an equivalence test shows both paths decide identically.chokepoint.py; gateways/equivalence.py; D53
Why embed OPA instead of running the server?So a clean clone reproduces the governance story with no external process. The engine sits behind a protocol; production would likely run the OPA server for bundle distribution and decision logs, which is one adapter.D17
Why two policy engines?Falsifiability. If swapping the engine changed an answer, the rules would live in the engine, not the catalog. Cedar covers the four pure authorisation controls; parity is tested over the golden set, boundaries and every fixture order.D22; test_policy_parity.py
How does tiering avoid being fitted to the first agent?Each control declares its own lowest tier and the shape it applies to; an agent's set is derived. The second archetype derived a different set with zero framework edits; a fixture test fails if anyone fits the catalog to one agent.D14, D39; test_governance_tiering.py
How do you test anything with a non-deterministic model?Controls are tested with scripted and fully hostile models, because the claim is about enforcement, not model behaviour. Quality is measured separately, with the answering model's identity recorded and retries only on effect-free rate-limit errors.D29; D71; pm D-PM-P5-r
What breaks first at a hundred times the load?Assumption Per-call signing if it goes through KMS, the evidence write path's single file per sink, and model quota. The design answers are head-sealing at boundaries, sharded append-only stores with anchors, and quota-aware routing; none is built yet.Chapter 33
What was the hardest bug?RT-11: an evidence sink that accepted the decision record and refused the action record let an approved refund execute unrecorded while audit still said VERIFIED. The fix reverses any effect whose record cannot be written, and taught us that one invariant was resting on another.D30; test_s4_evidence_integrity.py
What would you do differently?Name the agent's identity and directory from day one instead of comparing strings and fixing it twice; verify evidence signatures as soon as they became asymmetric; and namespace control ids across catalogs before forking.D33; Appendix G
Why should anyone believe a build mostly written by an AI coding agent?Because nothing depends on believing it: every claim has a test, the tests have falsifiers, an independent validator thread reviews each stage, and the semantics (taxonomy, catalog, rulings) were authored and ratified by a human. The decisions log records each ruling and its reason.ADR-0001; D49; D56; pm T3 reports
Is it a framework or a demo?A reference implementation of a framework: the semantics are reusable YAML, the machinery sits behind seams, and a whole framework version swap (ADK) touched pins and zero adapter code. It is not a product and does not claim production readiness.D48; claims card "don't say"

54.6Questions from a CISO

QuestionAnswerHonest limit
Can the agent bypass the checkpoint?It holds only governed tools, never the payment client; vendor SDKs are confined to adapters by an import-firewall test; out-of-process hosts go through gateways.A co-resident host with a local model server could get a text-only answer outside the gateway; it cannot act.
What about prompt injection?Retrieved text is fenced with a per-wrap nonce; a match taints the turn and blocks writes; and the refund is decided on facts read from the order system, so an injected instruction cannot raise a limit or forge an approval.Detection is a tripwire; residual RESID-01/02 keep a semantic classifier as a second tripwire, never the control.
Where are the keys?Signing is Ed25519; in live mode the private key is in Cloud KMS and never leaves it; verifiers hold only public keys.The committed sign-off uses a local synthetic key, so non-repudiation is claimed only for KMS signatures. Evidence signatures are not yet verified by the audit tool (F-01).
How do you stop self-approval?Approver and executor are resolved to directory subjects; approvers must be human subjects; the approval is signed over the exact act and spent once per intent.The approver kind is declared, not detected.
What if the policy engine or state store is down?Writes fail closed; a contended state transaction refuses with a named error; an unreachable directory is a distinct error, not "unknown user".Availability under failure has not been load-tested.
Supply chain: models and tools?Models are pinned and an impostor model gets no tool; MCP tools are pinned by a hash of name, description and schema, and a changed tool is withheld; unlisted endpoints are refused before contact.Only the synthetic MCP server is exercised.
Does PII reach logs or traces?The open log is an allowlist; free text goes to a capability-gated detail store; spans carry no arguments or results and use the same redaction policy.Synthetic data only; no DLP seam on outbound text in ARB.
What can't it stop?Eleven named residuals with reasons, in docs/defense/WHY_TRUST_THIS.md: for example approval fatigue is measured but not enforced, and a truncation inside the anchor window is declared, not caught.That is the answer; do not soften it.

54.8Questions about pm-agent

QuestionAnswerEvidence
Why LangGraph here and ADK in the reference build?pm-agent's work is a resumable, approval-gated planning graph, which a typed state graph with checkpoints fits; the runtime sits behind an owned orchestrator interface, and the import firewall keeps LangGraph inside it.ADR-0001; D-PM-2
Why did you stop trying to detect injection?Twelve rounds of fixes and held-out acceptance stayed at 56%; each fix fitted the corpus. Containment by construction is a property, not a rate.ADR-0005; D-PM-P5-q
What stops it doing what a ticket comment says?Effects are typed actions on retrieved keys; an eligibility policy on system-of-record facts decides each; written text is display-only; free-text-only suggestions go to a separate lane with provenance, out of batch approval.ADR-0005; D-PM-R1-30
Where does its data go?By default to hosted models via OpenRouter restricted to zero-retention, no-training providers with fallbacks off; Vertex for clients who won't route through OpenRouter; the answering model and provider are recorded and a mismatch is refused.ADR-0006
Will it run coding agents?Through one executor contract: a delegation is a typed action needing eligibility and a signed approval; the executor runs in its own sandbox with its own credentials; its output returns as a proposal verified against acceptance criteria. Coding agents join via ACP, with their permission requests mapped onto pm-agent's approval gate.ADR-0008
Why should we trust its memory?Scoped per principal and project, PII-redacted with check-digit validation, expiring within 30 days, MAC-signed; without a key it is a hint for retrieval only.D-PM-P5-i, -j, -l, -p

54.10Rehearsal

Your build The GR1 gate includes a readiness check that draws 15 rows at random from the 25 client questions. Use the same method for this chapter, at architect depth:

  1. Shuffle the questions in this chapter's four tables. Answer five aloud, cold, in under a minute each, naming the evidence.
  2. Check against the tables. Any answer without an artifact, or with an unqualified figure, is a miss.
  3. Run one demo end to end without notes, narrating what each line of output proves.
  4. Add a card for any miss; the monthly PROVE slot repeats the drill.

54.11Prove it

Defend cold · monthly PROVE
  1. RecallGive the ninety-second story of each build from memory.
  2. ApplyRun make demo-before-after and make demo-tamper, narrating what each line proves and which chapter explains it.
  3. ApplyAnswer your three "least liked" questions from Predict first using this chapter's pattern: two sentences, then the artifact.
  4. DesignA skeptic says "a scripted demo proves nothing". Construct the answer from three artifacts.
  5. Trade-offShould you close F-01 before the showcase or disclose it? Argue both and decide.
