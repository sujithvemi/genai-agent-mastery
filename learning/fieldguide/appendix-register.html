APPENDIX H

Living register

What this book is waiting for. The builds are work in progress, the platforms move monthly, and two agents are a small sample of a fleet. This register says what each chapter will revise, on what trigger, so the book grows with the builds instead of going stale behind them.

H.1How this register works

Every chapter that depends on something not yet built, measured or verified carries a dashed "Waiting on the builds" panel with a trigger. The build script collects all of them into the first table below each time the book is published, so the table is always complete and never edited by hand. The remaining sections are maintained by hand: items that belong to the book as a whole, facts with an expiry date, and directions for later editions.

When a trigger fires (a build phase closes, a weekly sync reports a module change, a platform announces a feature), the Learning Orchestrator opens the named chapter, revises it, re-runs the build, republishes, and removes the panel or rewrites its trigger. The weekly build-to-learning sync should list any trigger that fired that week.

H.5Future directions for the book

  • A second edition organised by archetype. Once the fleet has four or more archetypes, a part that walks each archetype end to end (tier, controls, enforcement placement, evidence, evals, operating model) would be more useful than examples scattered through chapters.
  • Worked client cases. Anonymised, generic versions of estates you assess (Capstone B and real pursuits, with client facts kept out), as case-study chapters.
  • Exercises with code. Pair each Part IV chapter with a lab in genai-agent-mastery/labs/ where the reader breaks a control and watches the conformance suite catch it.
  • An open-source edition. If the builds are open-sourced, a version of this book with the personal learning apparatus removed could serve as their architecture guide.
