PART VI · CHAPTER 35

Frameworks, SDKs and studios

Agent frameworks are now plentiful, opinionated and short-lived: two of Microsoft's were folded into a third in 2026, and OpenAI is retiring its visual builder within a year of launch. An architect needs to know what each family assumes, where governance can attach in each, and how to choose one without letting it own the architecture. Your reference build shows the strongest answer: run any framework as a host that can reach tools and models only through governed gateways.

35.1What a framework gives you

Generic Recall the seven harness subsystems (Chapter 1). A framework supplies some of them: the agent loop, model integration, tool binding and schemas, session state and memory interfaces, orchestration primitives (sequences, graphs, hand-offs, sub-agents), streaming, tracing hooks and deployment adapters. It does not supply your enforcement plane, your evidence, your identity model or your evaluation discipline. Every framework makes the first set easy; none makes the second set unnecessary.

35.2Three families

FamilyControl flowExamplesGovernance character
Graph or workflow firstYou define nodes and edges; the model works inside nodesLangGraph, Microsoft Agent Framework workflows, ADK workflow agents and graph networks, LlamaIndex workflowsEdges are code and testable; approval gates are interrupts; easiest to reason about
Model-driven loopThe model decides the next tool call until it answersOpenAI Agents SDK, Claude Agent SDK, AWS Strands, smolagentsFewer lines, more autonomy; every effect must be mediated outside the loop
Managed harnessThe provider runs the loop; you declare model, instructions and toolsAgentCore Harness, Claude Managed Agents, GEAP Managed Agents API, Foundry hosted agentsLeast code; your controls attach only at the provider's gateways and policies

The first prediction question has a qualified answer. A graph is easier to reason about, because the path is visible in code. But neither family is safe by construction: in both, the effect must be decided by an enforcement point the model cannot route around (Chapter 16).

35.4Low-code studios

Generic Studios let non-engineers build agents: GEAP Agent Studio (which exports to ADK), Microsoft Copilot Studio, Salesforce Agentforce Builder, ServiceNow's agent studio, Amazon Quick's no-code agents, and general automation tools such as n8n. They matter to an architect for two reasons. First, they create the agent sprawl an AICoE must govern, often faster than pro-code teams. Second, their governance is the platform's: environments, connector policies, data-loss prevention, publishing controls and the platform's registry. Ask four questions of any studio:

  1. Can its agents be exported to code or at least versioned and diffed?
  2. Can you test them against a golden set before publishing?
  3. Which connectors can a maker use, and who approves new ones?
  4. Does each agent get its own identity and an entry in a registry you can see?

35.6Where governance attaches

Generic Every framework offers interception points: ADK callbacks and plugins (before and after model and tool calls), LangGraph node wrappers and interrupts, OpenAI Agents SDK guardrails and tool wrappers, Microsoft Agent Framework middleware, Claude Agent SDK hooks and permission modes, Strands hooks. They are the natural place to call your PEP.

The second prediction question is the trap. An in-process hook is complete mediation only if every path to the effect passes through it. In practice there are bypasses: a tool implemented as plain code that the framework calls directly, a framework feature added in a minor version that calls tools a new way, a developer who registers a tool on a different agent object, or code that imports the business client directly. Hooks help; they are not a boundary.

Gotcha · default telemetry is egress

Some SDKs export traces to the vendor's endpoint by default. ARB's OpenAI Agents SDK host sets tracing_disabled=True because "traces would otherwise leave the host for a vendor endpoint. The governance evidence is the record." For a regulated client, that is a data transfer to check before the first pilot (the third prediction question).

35.7Frameworks as hosts behind gateways

Reference build D53 turned the bypass problem into an architectural rule. ADK runs in process, with its tools registered only through the chokepoint. Every other framework runs as an out-of-process host, in its own project at its own latest stable version, that reaches governance only through two gateways: a tool gateway (MCP in front of the chokepoint) and a model gateway (an OpenAI-compatible endpoint that enforces the model pin and meters the budget). Two hosts exist: LangGraph 1.2.13 and the OpenAI Agents SDK 0.23.1.

The host's code is ordinary framework code; the guarantees come from what it does not hold. "The host process holds no tool implementations and no model credentials", so a framework feature that calls tools a new way still has nowhere to call them except the gateway. Three further rules close the gaps between the two gateways: every request is signed with the host's session credential; the tool gateway admits a tool call only if the model gateway issued it in that turn, so the host cannot invent or edit one; and the model gateway refuses a tool result that is not the text the tool gateway served (D63). The same 25 golden and 39 red-team cases run through both hosts, and the decision-equivalence rule requires that they decide exactly as the in-process path does (tests/test_framework_hosts.py).

The pattern generalises beyond Python and beyond your builds: MCP and OpenAI-compatible model APIs are what current frameworks already speak, so any framework, in any language, can be governed this way. It is also the shape that the cloud platforms' agent gateways are converging on (Chapter 45).

35.8Keeping the choice reversible

  • Seams. Keep the framework behind your own interface (Orchestrator in pm-agent, RuntimeAdapter in ARB) and confine its imports with a firewall test (Chapter 7).
  • Currency policy. D53: each host pins the latest stable release at the start of a phase, a currency bump runs at least quarterly, and a host more than one major or two minor versions behind is a named residual, never a silent pin.
  • Equivalence as the upgrade gate. "A bump that changes any enforced decision is a finding, not a merge."
  • Pin what you use. D53 also removed ADK's convenience extra after it was found to cap an unused LangGraph version: "a convenience extra that constrains packages the build doesn't import is removed."

35.10In the room

In the room
  • "Which framework should we standardise on?" "One default per cloud, chosen on a short list of criteria, and an architecture in which the framework is replaceable. Your governance should not care which framework a team picked."
  • "Our framework has guardrails built in." "Use them as filters. The decision on any effect belongs at a gateway or enforcement point the framework cannot bypass, because the framework will change faster than your controls."
