PART I · CHAPTER 4

Retrieval and grounding

Retrieval decides what the model can know; grounding decides whether what it says is supported by what it was given. The first is an information-retrieval problem with well-known tools. The second can be made a control: a citation that the turn did not retrieve, or a policy claim with no retrieval at all, never reaches the user.

4.1Retrieval as a pipeline

Generic Retrieval-augmented generation is usually described as "search, then generate". In production it is a pipeline with a decision at every stage, and each decision changes what the model can be wrong about:

StageDecisionTypical failure
IngestWhich sources, who owns them, how often refreshed, what labels carriedStale or unowned content treated as truth
ChunkSize, overlap, structure-aware splitting (headings, tables)Answers split across chunks; tables destroyed
IndexLexical (BM25), vector (embeddings), or both; metadata and entitlementsIndex ignores permissions; embeddings miss exact identifiers
QueryRewrite, expand, decompose the questionThe model searches for the wrong thing
RankHybrid fusion, cross-encoder re-ranking, top-kThe right passage ranked eleventh
AssembleWhat goes into context, in what order, fenced howLost in the middle; injected text unfenced
GroundDoes the answer rest on what was retrieved?Fabricated citations; unsupported claims

Agents add one more choice: retrieval can be a tool the model calls when it decides to (agentic retrieval), rather than a fixed step before generation. That gives flexibility and a failure mode: the model can decide not to search at all and answer from its weights.

4.2Lexical, semantic, hybrid

Generic Lexical search (BM25 and relatives) matches terms; vector search matches meaning through embeddings. Each misses what the other catches: embeddings blur exact identifiers ("PLAT-104", a policy number, an error code), while keyword search misses paraphrase. Hybrid search runs both and fuses the rankings (reciprocal rank fusion is the usual method), often followed by a cross-encoder re-ranker. For enterprise agents, where questions mix identifiers and concepts, hybrid is the sensible default.

Two observations temper the enthusiasm for vectors. The harness study (Chapter 1) found that none of eleven production coding agents uses embedding retrieval over code: they search deterministically, just in time. And deterministic retrieval is easier to govern: the same query returns the same results, which makes tests exact and evidence reproducible.

4.3What your builds chose

Your build ARB's default retriever is a deterministic Okapi BM25 implementation with no dependencies and no network; ties are broken by document id, so the same corpus and query always give the same ranked hits, safe to assert in tests and to cite in evidence. An embedding retriever sits behind the same Retriever seam, off by default; a hosted vector store would be another binding. The seam knows only Document (id, text, metadata), not knowledge-base articles, so it serves both agents.

pm-agent pm-agent does not index Jira at all. It reads on demand through the Jira adapter using the requester's identity, behind a read-through cache keyed by the user's entitlement scope, the resource and a version or time-to-live; vector memory was deferred until a concrete need appears (ADR-0002). The design choice is about authority as much as freshness: a standing mirror would need its own permissions model; reading through as the user inherits Jira's.

4.4Grounding as a control

Your build GAP-15 is the clearest failure in the build's history. Asked about a student discount, the live model made no search_kb call at all and answered with a citation to [KB-0000], an article that does not exist. The instruction asked for search first and citations; nothing checked either. CTL-0015 is the check, run after the turn and before the answer reaches the customer:

  • Every [KB-####] in the answer must be an id that search_kb actually returned this turn. The chokepoint saw those calls, so the retrieved set is evidence, not the model's word.
  • An answer that asserts policy in a turn with no retrieval at all is refused.
  • A failure is not softened or annotated: the answer is replaced with the authored refusal, and the verdict goes to evidence with both id sets (cited ⊆ retrieved).

The heuristic had a residual: an answer could state policy without citing anything and slip past a check that only inspects visible citations (RESID-03). CTL-0026 closed it by construction, by making the only acceptable answer a typed object with at least one citation from this turn's retrieval (Chapter 2), with a monotone support classifier able to hold an answer whose citations do not support what it says.

Generic The pattern generalises beyond knowledge bases. "Cited ⊆ retrieved this turn" works for any identifier the system can observe being fetched: ticket keys, policy numbers, document ids, URLs. pm-agent's rubric scores the share of plan items that cite only retrieved keys, and its output checks quarantine items whose identifiers were not retrieved.

4.5Saying what you didn't find

pm-agent A grounded answer from partial retrieval can still mislead: the plan is accurate about the issues it saw and silent about the ones it could not fetch. pm-agent has a control for exactly this, degraded-context disclosure: when retrieval was partial (a fetch failed, a scope was refused, a limit was hit), the plan says so. It was ruled a genuine control rather than a nicety (D-PM-P3-g), mapped to the transparency and human-AI configuration risks in the standards. The general rule: an agent's output should disclose the limits of what it looked at, not only cite what it found.

4.6Evaluating retrieval

Generic Evaluate the retriever separately from the answer, or a good model will hide a bad retriever and vice versa:

MetricAsks
Recall@kIs the passage that answers the question in the top k?
Precision@k, MRR, nDCGHow high, and how cleanly, is it ranked?
Citation precisionOf the citations in answers, how many were retrieved this turn? (ARB's live report: 7 of 7 on 2026-10-16)
Faithfulness or groundednessIs every claim in the answer supported by the retrieved text?
Abstention qualityWhen the answer is not in the corpus, does the agent say so?

Ragas and DeepEval implement most of these; the hard part is the labelled set of questions with known supporting passages, which has to be built from real questions and kept current as the corpus changes.

4.9In the room

In the room
  • "Our assistant always cites its sources." Ask whether anything checks that each citation was actually retrieved in that answer's turn, and what happens when retrieval returns nothing.
  • "Should we build a vector database of everything?" "Only if a read-through to the systems of record, with the user's permissions, is too slow; a mirror is a second copy of your data with its own access problem."
