PART I · CHAPTER 1

Anatomy of an agent harness

An agent is a model plus a harness, and almost everything an architect decides and a governance programme controls lives in the harness: the loop, the tools, the context, the permissions, the extensions, the orchestration. Knowing its anatomy tells you where a control can attach and where it cannot.

1.1Model plus harness

Generic The cleanest definition comes from a 2026 source-code study of eleven production coding agents (Barbaste et al.): an agent is a model plus a harness; the harness is everything except the model, the runtime that couples a model to the world through a loop, tools, context management, safety controls, orchestration and extension surfaces. The study is careful about four things a harness is not, and the distinctions are useful in client conversations:

TermWhat it isRelation to a harness
ScaffoldThe structural code: the loop and the registriesNear-synonym; the harness is the shipped runtime that embeds a scaffold
Agent frameworkA library a developer imports to build an agent (LangGraph, ADK, CrewAI)Used to build harnesses; the line is blurring as harnesses become importable SDKs and framework vendors ship harnesses
Evaluation harnessWraps an agent to run it against tasksSame word, opposite direction of wrapping
Orchestrator or meta-harnessCoordinates harnesses from above, with no editing loop of its ownA consumer of harnesses; pm-agent's executor role is one (Chapter 6)

Two consequences matter for governance. First, two agents on the same model can behave very differently because of their harnesses, so governing "the model" governs little. Second, the harness is where a control can sit on the path to an act; the model can only be asked.

1.4The autonomy ladder

Generic Autonomy is a dial, not a switch, and placing an agent on it is the fastest way to make a governance conversation concrete. Your tiering axis autonomy encodes three of the four rungs.

RungThe agent mayARB axis valueGovernance grows by
ObserveRead, search, summarisesuggests (with read-only action class)Registration, data scope, logging
AdviseRecommend; a person actssuggestsQuality evals, disclosure, grounding
Act with approvalExecute after a person approves that actacts-with-confirmationPer-act approval, separation of duties, policy before each act, full evidence
Act autonomouslyExecute within limits, no per-act approvalacts-autonomouslyValue and volume limits, live monitoring, kill switch, continuous testing, executive acceptance

pm-agent pm-agent scored its write-capable profile as acts-with-confirmation rather than leaving it at suggests, because an agent that proposes a write which executes after a person confirms is, by the axis definition, acting with confirmation (D-PM-P4-a). Score the designed behaviour, not the comforting one.

1.5What the field's code shows

Generic The source-code study's findings bear directly on how you govern harnesses you did not build:

  • No general-purpose agent framework in any runtime. Across about four million lines, none of the eleven imports LangChain, LangGraph, AutoGen or similar; loops are hand-rolled. Governance that depends on a framework's hooks will not reach these agents; governance at a gateway, a tool server or the system of record will.
  • Behavioural policy is moving from prompt prose into configuration. Hooks, permission files and settings replace "please don't" in the system prompt, which is the harness vendors arriving at "an instruction is not a control" from the other side.
  • Safety is a choice, not a consequence of scale. Some of the largest harnesses ship with no OS-level isolation and spend instead on content-borne threat defence and syntax-aware permissioning. Do not assume a popular harness is sandboxed; check.
  • Skills now lead MCP in adoption (9 of 11 versus 8 of 11), with registries, trust tiers and the first agent-authored skills. Extensibility has become a supply chain, with the integrity problems of one.
  • ACP found a third role: harness hosting. OpenHands runs Claude Code, Codex or Gemini CLI as interchangeable back-ends, and a meta-harness (Databricks' Omnigent) orchestrates eleven vendor harnesses behind one API. The harness has turned from a tool into a platform.
Check before quoting

Harness versions, licences and ownership change monthly (in 2026 alone: Gemini CLI's consumer service moved to the closed Antigravity CLI, Goose moved to the Linux Foundation, Aider entered community maintenance). Quote the study's findings with its date (July 2026) and re-check any product fact.

1.6Where governance attaches

Generic Not every attachment point is equal. A control is only as strong as its position relative to the effect:

AttachmentCan be talked around?Covers agents you didn't build?Example
System promptYesNo"Never refund more than the order total"
Harness hook or permission configNo, if the harness enforces itOnly that harnessPre-tool hooks; command allowlists
In-process chokepoint behind a seamNoOnly agents on your chassisARB ToolChokepoint
Tool or MCP gatewayNoYes, for tools it frontsARB tool gateway; platform agent gateways
Model gatewayNo, for what it seesYesPinning, budgets, screening
System of record's own permissionsNoYesThe agent's identity in the CRM

Your build ARB's design follows from this table: agents built on its chassis go through the in-process chokepoint, and agents built on other frameworks (LangGraph, OpenAI Agents SDK) run as out-of-process hosts whose model and tool traffic goes through gateways driving the same plane (D53). Every golden case and end-to-end red-team attack produced the same decisions through all three hosts.

1.9In the room

In the room
  • "We've standardised on one model, so our agents are consistent." "The harness decides more of the behaviour than the model: which tools, what context, what permissions, what happens between steps. Standardise the harness seams and the controls on them."
  • "Can you govern the coding agents our developers use?" "From the outside: their permission configs and sandboxes, a gateway in front of the tools and repositories they touch, and their identities in your systems. From the inside only if they run on a chassis you control."
