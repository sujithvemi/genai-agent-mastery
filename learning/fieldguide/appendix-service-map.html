Service map across platforms

One place to translate a capability into the service that provides it on each major platform: first the agent-specific services, grouped as Google groups its agent platform and extended with what that grouping leaves out, then the ordinary foundation services every agent system still runs on. Names only; the judgement is in the chapters.

I.1How to use this map

Use it to answer "what is the AWS (or Azure, or Google) equivalent of this?" in a design review or an interview, then follow the link to the chapter that says whether the equivalent actually meets the need. Equivalence of name is not equivalence of guarantee: AgentCore Policy and GEAP's IAM access policies are both "policy on the gateway", but one decides on tool arguments and the other on destinations (Chapter 45 rates them). Three conventions:

  • A dash means no first-party service for that capability; the gap is usually filled by the last column or by your own build.
  • Verify marks a name or status checked against announcements rather than documentation, or one that was preview when written.
  • The foundation table in I.3 is assembled automatically from the "Managed services across clouds" section of each Part V chapter, so it changes when they do.

I.4Beyond the three clouds

Generic Agents also arrive from data platforms (Databricks Agent Bricks with Unity AI Gateway; Snowflake Cortex Agents with Cortex AI Gateway), SaaS platforms (Salesforce Agentforce, ServiceNow AI Agents with AI Control Tower, IBM watsonx Orchestrate) and model providers' own platforms (OpenAI's Frontier and Agents SDK; Anthropic's Claude Agent SDK and Managed Agents). Their equivalents of the rows above are compared in Chapter 44, and the hands-on tools for each lifecycle stage in Chapter 46.

I.5Keeping it current

Service names in this map changed several times in the year before it was written (Google regrouped its Vertex AI agent services as the Gemini Enterprise Agent Platform; Azure AI Foundry became Microsoft Foundry). Re-check names quarterly with the capability map in Chapter 45.

Waiting on the builds

Re-verify the agent services table against each platform's release notes, remove Verify tags that are confirmed, and add rows for new capability families. When ARB or pm-agent deploys to a second platform, add a column note for which services the build actually uses there.
