# System Design Track — the agent is only as good as the system around it

**Updated:** 2026-11-01 (sync: SD-07/10/11 cells, PM R1-S2; earlier: field guide wired in; SD-13…SD-16 added, L-24). **Why:** an agent that can't be served, secured, scaled, deployed and operated with ordinary system-design engineering has no production value. This track covers the end-to-end architecture around the agent, not only the agent.

**How it runs:** every SYS rep = learn one concept (≤ 25 min: the field guide chapter first, other GROUND sources for depth) **+ apply it immediately** by writing or revising one section of `design/pm-agent-at-scale.md`, the production architecture for your own pm-agent. The design doc is the retention device: each concept lands on a system you know, and by the end you own a defensible end-to-end design you can present.
